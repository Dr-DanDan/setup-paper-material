# setup-paper-material

[English](README.en.md) | 简体中文

一个按项目启用的 Codex 技能，用于整理论文插图、文献资料和研究结论，并维护来源依赖、工作进度及已认可材料的登记记录。

**仅在用户主动调用时启用。** 由用户决定哪些项目需要论文材料管理；启用后，项目内的 agent 持续遵守生成的管理规则。支持 Git 与非 Git 项目。

## 安装与使用

将本仓库下载或克隆为个人技能目录下的 `setup-paper-material` 文件夹，确保 `SKILL.md`、`agents/` 和 `assets/` 一起保留。个人技能目录为 `$CODEX_HOME/skills`；未设置 `CODEX_HOME` 时使用用户主目录下的 `.codex/skills`。克隆私有仓库需要相应访问权限。

在需要管理论文材料的项目中明确调用：

```text
$setup-paper-material 为当前项目初始化论文材料管理。
```

调用本身即授权初始化，无须再次确认是否启用。若已有材料目录，技能会保留已有内容并补齐缺失项；规则冲突时先询问。默认目录名可由用户明确覆盖。

后续可指定材料整理或登记任务：

```text
$setup-paper-material 整理检测概率曲线材料，记录来源依赖并更新进度。
```

```text
$setup-paper-material 将刚才确认的检测概率曲线 v1 check in。
```

## 项目中会创建什么

```text
paper_material/
├── AGENTS.md
├── README.md
├── TODO.md
├── CONTEXT.md
├── docs/
│   └── check_in/
│       └── README.md
└── illustrations/
    └── check_in/
        └── README.md
```

同时在项目根 `AGENTS.md` 添加规则入口，保留其他规则。插图主题目录随实际任务创建。

| 位置 | 职责 |
| --- | --- |
| `paper_material/AGENTS.md` | 项目内持续生效的材料管理规则 |
| `paper_material/README.md` | 来源依赖、结果、适用条件、材料路径与状态索引 |
| `paper_material/TODO.md` | 仅跟踪论文材料整理的进行中、已完成和待完成工作 |
| `paper_material/CONTEXT.md` | 论文术语表，区分已确认术语与待确认候选 |
| `docs/` | 文献资料、分析说明和结论总结，按需分主题 |
| `illustrations/<主题>/` | 同一主题的插图、可编辑源文件、脚本和导出文件 |
| 两个 `check_in/` | 已获认可并授权登记的版本及其来源索引 |

## 论文术语

项目开发任务以项目根 `CONTEXT.md` 为主；论文写作以 `paper_material/CONTEXT.md` 为主，覆盖标题、摘要、正文、图注、坐标轴等所有面向读者的内容，不受文件位置限制。混合任务分别使用对应术语并记录映射，定义冲突时先澄清。项目根 `AGENTS.md` 提供明确的读取入口，不依赖读取普通文件时自动加载子目录规则。

首次创建论文术语表时（包括为旧项目补齐），技能先询问：**扫描项目所有资料，还是创建空结构？** 重复调用保留已有词表，不重新询问。

- 扫描先盘点项目，再优先读取其他 `CONTEXT.md`、说明文档、论文草稿、图表标签和相关代码说明；数据、权重通过元数据与说明理解。来源记入词条，扫描范围和未覆盖材料记入材料 README。
- 空结构包含边界说明、“已确认术语”和“待确认术语”分区，不自动填入推断的名称。
- 每条包含首选名称、定义和适用范围，按需补充中英文对应名、缩写、历史别名、项目术语映射、来源与确认依据。研究背景、实验事实和任务记录不放进术语表。
- 从项目词表导入的条目默认是论文候选；用户可批量确认，已有明确论文用词约定可直接收录。同一概念在同一语言中使用一个首选名称，允许登记的对应名、缩写和语法变化。
- 术语经用户确认即生效，无须 check in。写作中的核心新术语或歧义需澄清，相关段落保持待确认，不影响其他明确内容的推进；每次写作或修订结束检查用词一致性。
- 术语修改需确认并识别影响范围；更新授权范围内的工作稿，已登记材料仍按修订与重新授权登记流程处理。

## 认可与 check in

材料状态区分为：**整理中 → 待认可 → 已认可待登记 → 已登记**。

- “这张图可以了”可表示认可，但不自动授权登记。只有明确说 **check in** 或明确授权登记才执行。
- 评价对象或意图不清时，agent 在本轮其他已授权工作结束后提问，确认前保持未登记状态。
- 登记复制认可文档，或采用的插图、可编辑源文件及必要的小型脚本／配置，并保留工作源材料。大型数据、模型权重和实验结果通过路径及版本引用。
- 登记索引记录来源、版本、简介、认可及授权依据、日期；插图还记录已确认的视觉细节。
- 修订版需要新的认可及登记授权，保留历史登记版本，并标明当前采用版本。论文优先选用当前采用的登记材料。

这里的 check in 指论文材料登记，与 Git commit 或 push 无关。

## 范围与仓库文件

技能负责材料管理；绘图、分析、文献整理或写作根据具体请求执行。它不承担整个项目的开发管理，也不在初始化时清理、删除或迁移旧目录。原始实验文件保留原位置。

- [SKILL.md](SKILL.md)：初始化、维护流程和完成检查。
- [项目规则模板](assets/paper-material-AGENTS.md)：写入项目的日常材料管理规则。
- [调用策略](agents/openai.yaml)：通过 `allow_implicit_invocation: false` 配置仅手动调用。

本说明提供中英文版本；技能指令与项目规则模板目前使用中文。
