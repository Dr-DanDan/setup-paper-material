# 论文材料管理规则

本规则适用于本项目的 `paper_material/` 及全部子目录。该项目由用户明确启用论文材料管理；后续 agent 处理这些材料时持续遵守本规则，无须用户再次调用初始化 skill。用户明确指定的处理方式优先。

本规则中的论文用词要求也适用于该项目存放在其他目录的论文内容。处理论文材料或开展论文写作前，通过项目根规则入口显式读取本文件；不假定读取普通文件会自动加载本文件。

## 论文术语与任务场景

- 项目开发任务以项目根 `CONTEXT.md` 为术语依据（若存在）；论文撰写、修订与审校以 `paper_material/CONTEXT.md` 为依据。两者分别是项目术语表与论文术语表，不能混用；混合任务分别采用对应术语并记录映射。
- 论文术语表仅记录术语含义、适用范围和表达关系，不承担研究背景、实验事实、结论、进度或实现决策记录。维护规则集中在本文件。已确认部分约束论文用词，待确认部分仅为候选。
- 写作前读取论文术语表。约束覆盖标题、摘要、正文、图注、表头、坐标轴、图例及补充材料，不受文件存放位置限制。代码变量、原始数据字段、文件名、文献原文保持原名，需要时在词条中记录映射。
- 同一概念在同一语言中使用一个首选名称，允许明确记录的中英文对应名、缩写及必要语法变化；历史别名用于识别旧材料，不作为正文的替换同义词。含义不同的概念不强行合并。
- agent 可提取候选，只有含义与首选名称具有用户确认依据的词条才能进入“已确认术语”。已有明确论文约定可直接收录；项目术语表中的条目默认作为论文候选，可批量请求确认。名称不同但含义相同时记录映射，定义或适用范围冲突时询问用户，不自行合并或修改项目术语表。
- 普通通用词无需逐一登记。写作遇到未登记的核心概念或歧义时，提出候选并询问；继续其他明确内容，将受影响段落标记待确认，不将自拟术语作为已确认用词交付定稿。
- 论文术语表是持续维护的管理文档，词条经用户确认即生效，无须 check in。修改已确认含义或首选名称需要新的确认，记录其依据，并列出受影响内容；在本次授权范围内更新工作稿。已登记材料按下述历史版本规则形成修订候选，经认可及登记授权后另存新版，不直接覆盖。
- 每次完成论文写作或修订时，检查本次涉及内容是否遵守已确认术语，报告待确认条目及未解决歧义。

## 职责与材料位置

- `README.md` 是结论索引，记录每项材料的来源依赖、结果、适用条件、路径、版本和认可／登记状态。
- `TODO.md` 仅记录论文材料整理的正在进行、已完成和待完成工作。项目开发、训练调度和代码维护沿用项目原有管理方式，在此只引用相关依赖或阻塞。
- `docs/` 保存文献资料、分析说明和研究结论总结，可直接放文件，相关材料较多时再按主题分目录。
- `illustrations/` 保存论文插图及对应源文件、绘图脚本和导出文件。按内容创建 `illustrations/<主题>/`，同一主题材料放在一起。
- 若下一步准备直接向 `illustrations/` 根层创建或写入文件，先询问：“是否需要创建子文件夹，或者需要在哪个已有子文件夹中进行保存”。位置明确后再写入；已有用户指定主题目录时直接使用。
- 实验原始数据、模型权重及训练／评估程序保留原位置，通过路径引用。初始化材料管理不清理、迁移或删除既有目录。

## 来源、结果与进度

- 创建或修改材料时同步根层 `README.md`。依赖应能定位到实际数据／实验结果、代码或配置版本、生成脚本或命令、文献出处及影响结论的条件；不适用项可省略。非 Git 项目使用可定位的文件版本或快照，不要求引入 Git。
- 仓库内路径以仓库根为基准；非 Git 项目以项目根为基准。项目外来源使用完整路径或稳定链接。详细推导和复现说明放在对应主题文档，由总索引引用。
- 结果写明实际发现和适用条件，区分有证据的结论与待验证判断。材料制作完成不等于结果已证实，也不等于用户认可或授权登记。
- 开始、完成或遇到阻塞时同步 `TODO.md`，关联材料及依赖。保持已有记录；管理结构初始化不产生研究结论。

## 认可与登记授权

按实际证据记录状态，不要求用户逐一说出状态名称：

| 状态 | 判定 |
| --- | --- |
| 整理中 | 材料仍在制作、分析或核查 |
| 待认可 | 候选版本已形成，尚无明确用户认可 |
| 已认可待登记 | 用户认可具体材料／版本，但尚未授权登记 |
| 已登记 | 用户已授权登记，副本和登记记录均完成 |

- 只有用户明确说“check in”或明确授权登记，才执行登记。指向明确候选版本的 check in 请求同时表达对该版本的认可和登记授权；若对象或版本不明，先澄清。
- “这张图可以了”“采用这个版本”等指向明确对象的认可可标记为“已认可待登记”，但不自动登记。在本轮其他已授权工作结束后的最终回复中询问是否 check in。
- “不错”等认可对象或意图不清的评价保留原状态，在本轮工作结束时询问认可对象及是否授权登记。等待答复期间继续独立的已授权工作，不登记候选材料。
- 文件名含 `final`、自动检查通过或 agent 自评不构成用户认可或登记授权。已明确作出的认可与授权对其指定材料／版本持续有效，无须重复询问；不外推到其他材料或修订版。

## check_in 与历史版本

- `docs/check_in/` 和 `illustrations/check_in/` 保存已认可并获授权登记的材料，是论文选用的最高优先级材料区。插图存入 `illustrations/check_in/<主题>/`。各区 `README.md` 是登记索引；其存在不代表已有认可材料。
- 登记采用复制，保留工作目录中的源材料。文字材料复制认可文档；插图复制采用的导出图、可编辑源文件及复现该版本所需的小型脚本／配置。大型原始数据、模型权重及实验结果通过路径和版本引用。检查所复制脚本的相对依赖，必要时记录从源工作目录复现的方式。
- 登记前确认源文件仍是用户认可的版本；若已变化，定位认可快照或向用户澄清，不能将新内容当作旧版登记。复制后校验内容一致，再写入已登记状态。
- 在对应 `check_in/README.md` 逐项记录材料标识、登记文件路径及版本、源材料路径及版本、简介、用户认可依据、登记授权依据和相关日期。依据应可定位到会话或批注。会继续修改的来源使用可定位快照、版本号或内容指纹，配合稳定路径追溯。
- 插图另记录共同确认的线形、排布、坐标轴名称及单位、图例等视觉细节；无对应要素时注明不适用。
- 修改已认可的实质结论或视觉细节，先在普通工作目录形成修订候选。修订版再次获认可并授权登记后，保存为新的版本，不覆盖旧登记文件。用版本号区分，索引标明当前采用版本和历史版本；后续论文引用优先使用当前采用的登记版本。
- 相同材料的同一版本已登记时沿用现有记录，不制造重复副本。不同材料的结论冲突时保留已有登记材料并说明差异，不以草稿自动替换。
- 完成登记后同步根层 `README.md` 的登记路径、版本和状态，以及 `TODO.md` 的进度。
